Devin Incident Response Demo: Walkthrough

"Reps keep getting logged out": from a Slack message to a tested fix, using a copy of ZoomInfo's open-source gtm-ai-cli
Please note: The bug in this demo was planted by us on a copy of the public, MIT-licensed gtm-ai-cli repo. It is not a real ZoomInfo incident. Nothing was merged or deployed, and no ZoomInfo system or account was touched.

The situation

We set up a fake customer emergency. After an update, sales reps kept getting kicked out of the tool, worst when they ran several bulk data jobs at once. Support raised a ticket that described the symptom only, not the cause.

What Devin did

Someone posted one message in a Slack incident channel and tagged @Devin. Devin replied within 20 seconds and, about 2 minutes later, posted:
  • The cause: a recent "cleanup" change dropped a "× 1000", so a login meant to last 1 hour was saved as lasting 3.6 seconds. Every login looked expired right away, and parallel jobs tripped over each other trying to log back in.
  • The fix: one line of code.
  • Proof: 3 new tests that fail with the bug and pass with the fix, so it can't quietly come back.
  • A proposed change (a "pull request") for an engineer to review. In the same thread it also gave a two-sentence summary for a VP.

Outcome

About 2 minutes from Slack message to cause, fix and proposed change. All 151 tests pass, and nothing went live without human approval.

  4. 4
    The root cause
    Commit 173ebc5 ↗

    The change that caused the incident (the bug we planted for this demo), titled "refactor: simplify token expiry bookkeeping". It looks like a harmless cleanup, but it dropped a "× 1000". A login meant to last 1 hour (3,600 seconds) was saved as if it lasted 3,600 milliseconds, about 3.6 seconds. So the tool treated every new login as already expired. When several jobs ran at once, they all tried to renew the login at the same moment, and all but one got logged out. All 148 existing tests still passed, so nothing caught it.

Key takeaways

  • One Slack message in, finished work out. No one had to stop their own work to dig through code.
  • It found the cause, not just the symptom. Devin traced the error back to the exact change that introduced it.
  • It proved the fix. New tests reproduce the problem, so it can't quietly come back.
  • People stay in control. The fix arrives as a pull request for an engineer to review. Nothing merges or deploys on its own.
  • Everything is on the record. The Devin session shows every step it took.
